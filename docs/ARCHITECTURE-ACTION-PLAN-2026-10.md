## 执行顺序与验收

### 1. 隔离服务端配置与处理凭据风险

- 状态（2026-10-02）：代码与本地构建验收完成。`src/shared/lib/env.ts` 现在只读取显式公开的 `VITE_*` 配置；服务端必填项继续由启动校验和数据库入口负责，已移除硬编码数据库默认值。
- 本轮证据：3 个环境配置回归测试通过，lint、typecheck、production build 通过；重建后的 `dist/client` 不再匹配旧连接串，且未匹配 `.env` 中数据库、认证和微信密钥值。
- 待处理：凭据是否仍有效、轮换、历史清理、已发布静态资源和缓存范围，以及生产重新发布，均未在本地完成。

- 检查 `env.ts` 的所有消费者，保留页面需要的公开配置；服务端必填配置缺失时明确失败，不回退到硬编码凭据。
- 去掉数据库连接串默认值，确保客户端导入链不携带数据库、认证密钥或其他服务端配置。
- 增加一个定向回归检查；重建客户端后扫描产物，只输出匹配数量和文件位置，不输出秘密。
- 如果凭据仍有效，协调轮换并更新运行环境；评估 Git 历史、已发布静态资源和缓存中的暴露范围。

验收：配置缺失的失败行为和公开配置行为正确；新客户端产物没有原连接串或服务端秘密。代码修复、凭据轮换、重新发布分别记录状态；未轮换时不能宣称风险全部解除。

### 2. 验证真实鉴权与错误契约

- 状态（2026-10-02）：核心 ServerFn 与包装鉴权分支已完成本地行为验收。未登录统一返回 `401`，已登录但无管理员角色返回 `403`；业务处理器在拒绝分支不会执行，ServerFn 错误中间件继续保留 `UNAUTHORIZED` / `FORBIDDEN` 契约。
- 本轮证据：`tests/unit/middleware.test.ts`、错误中间件和 AI ServerFn 鉴权测试共 11 项通过；仍未进行真实浏览器登录态和部署环境 HTTP 验收。

- 沿 `src/start.ts`、`authMiddleware`、`requireUser`、`requireAdmin`、`requirePermission` 和实际 ServerFn / API Route 核对保护位置。
- 为未登录、普通用户访问管理功能、合法管理员、资源越权和无效输入补最小行为测试，验证业务读写没有先于权限检查发生。
- 检查 session 缓存、角色组合和权限错误的返回契约。框架重定向、流式响应与内部错误保持各自语义。
- 对旧 `src/middleware.ts` 记录保留或删除决定；删除须另获授权，不先做无消费者的工厂化。

验收：实际入口的拒绝和允许分支可复现，敏感操作有服务端保护，错误不泄露内部信息。单测通过不替代登录态 HTTP 验收。

### 3. 收紧边界，再逐项收口 admin

- 状态（2026-10-02）：边界检查的第一切片完成。检查范围从已注册模块的 `shared/` 扩展到模块全部源码，覆盖静态、动态和相对导入；兼容 admin 入口收敛为显式白名单，注释中的伪导入不会再绕过检查。navigation 的 admin 路由继续通过模块入口挂载。
- 本轮证据：模块边界测试 13 项通过，lint、typecheck 通过。当前只完成边界约束加固，未宣称 identity、organization、rbac 全部迁移完成。

- 区分拥有业务数据和公共能力的模块，与 dashboard / mobile / settings 等页面组织目录；不要求每个目录都注册。
- 检查实际消费者，补齐相对路径、动态导入、未注册业务代码和数据库访问别名的约束缺口；优先复用现有 TypeScript 解析能力。
- 收紧兼容入口白名单，防止跨模块访问通过换 import 写法或客户端别名绕过检查。
- 第一批优先收口已有 `navigation` 模块对应的 admin 适配层；随后核对 identity、organization、rbac 的所有权与耦合，再决定每个能力的目标位置。
- 每个切片先补行为证据，再迁移消费者，验证后提交；保持 URL、权限、数据结构和外部调用契约不变。

验收：边界测试能主动发现新增越界；迁移切片的相关测试和类型检查通过，兼容入口只做转发。跨模块事务存在时先解决契约，不用文件搬迁掩盖耦合。

### 4. 验证数据库与发布治理

- 明确 PG schema 分片、生成客户端和有效迁移目录，检查干净 checkout 能否按记录的命令完成生成、检查和构建。
- 在隔离的临时数据库回放 PG 迁移并与合并 schema 比较；迁移状态正常不等于没有 schema drift。
- 检验 CI 实际启动顺序、依赖安装、生成步骤及必要环境条件；本地 `pnpm check` 通过不等于远端 CI 已通过。
- 检查 `deploy:preflight` 的失败分支、健康检查响应和超时；仅存在构建文件不证明产物属于待发布提交。
- 旧 SQLite 迁移先确认用途与归档方案，再决定是否删除；发布回滚和数据库恢复分开设计。

验收：干净 checkout 可复现，迁移回放与 schema 一致；preflight 对缺配置、缺产物、迁移异常和错误健康响应正确失败。外部数据库、CI、部署与回滚演练分别给证据。

### 5. 用测量决定性能与日志改动

- 测登录、管理列表、AI 会话三条核心路径的请求瀑布、压缩传输量、加载时间与渲染行为，并保留相同条件下的前后对比。
- 只有确认不需要首屏加载的依赖才延迟加载；不把改警告阈值或增加 `manualChunks` 当成性能成果。
- 针对现有日志队列检查积压上限、失败处理、退出时刷新和审计记录可靠性；先复现问题再修改。
- UI 组件按真实消费者评估，不按低频标签统一删除；移动端补关键滚动、弹窗和错误态验收。

验收：改动有可重复的性能收益，核心交互和可访问性不回退；日志失败行为与可靠性限制明确记录。
